## 二、原始路线（PROJECT_VISION.md 的四阶段）vs 实际

PROJECT_VISION.md 写的是四阶段，其中前三阶段的定义是：

| Phase | 原始目标 | 时间 | 当前状态 | 证据 |
|---|---|---|---|---|
| 1 | 模块库 4 → 10+ | 1-2 月 | ✅ **完成** | 已有 24 function category / 8 family（`function_coverage.json`） |
| 2 | 蓝图 12 → 22（含嵌套） | 2-3 月 | ✅ **完成** | 25 blueprints（含 4 synthetic），嵌套解析已实现 |
| 3 | 自动优化（GA vs 随机搜索） | — | ❌ **未达标** | CHANGELOG v2.x 早期：`0/7 优于随机`，明确写"不宣称" |
| 4 | 商业化开发者工具 ¥100-1000/月 | — | ⚪ **未启动** | 无定价页、无付费路径 |

**Phase 3 未达标的原话**（PROJECT_VISION.md 里就写了）：
> ✅ 结构精简：GA 自由优化 -84% 线成本
> ✅ 结构稳定性：6/7 拓扑模块级故障隔离
> ❌ 计算力：已实测为负（0/7 优于随机），**不宣称**

**这是 PROJECT_VISION 自己承认的失败**，不是评估者找茬。项目从一开始就把"计算力优势"这条从宣称里删了。

### 事实上发生的转向

从 CHANGELOG 看，v2.27.0 之后主线从"进化速度证明"转向"证据驱动 + 门禁加固"：

| 版本段 | 主线性质 | 代表版本 |
|---|---|---|
| v1.0 → v2.26.0 | 单元/模块/组合器构建 | 大量新增 |
| v2.27.0 → v2.29.0 | 加连接组（cel / larva） | 从"设计空间"到"实证证据" |
| v2.30.0 → v2.36.0 | **审计 + 回源核实** | 7 版连续修 caveat、口径、字段语义 |
| v2.37.0 → v2.40.0 | 转向：功能分类轴 + 代价轴 + 组合语义 | GATE 11、GATE 13 |
| v2.41.0 → v2.44.0 | 补齐 + 门禁加固 | GATE 13 行为学验证 |
| v2.45.0 → v2.46.0 | 词表收词 + 斑马鱼骨架 | GATE 14 |

**关键观察**：**v2.30.0 到 v2.36.0 的 7 版全是审计**（不是新增功能，是纠正之前的错误）。这不是"回归测试"级别的返工——这些是"数据对、语义错"级别的返工。比如 v2.34.0 抓出「1,560 无官方注释 52.77% 是对的，但把 frontier 类名当注释裁定是错的」；v2.36.0 抓出「`_unannotated` 是模态兜底不是无注释」。

**结论**：项目**没有偏离愿景**（愿景里就承认了 Phase 3 不宣称），但**实际做的事**已经从"证明超越生物学"变成"构建可追溯的生物学证据库 + 强门禁"。这个转变**没有在 CHANGELOG 顶端宣告**，但事实上发生了。

## 三、是否"如预想在推进"

### 是的地方

1. **模块库扩展**（Phase 1）——完成，24 function category / 8 family 已建矩阵
2. **蓝图扩展**（Phase 2）——完成，25 blueprints 含嵌套组合
3. **可追溯性**——116/116 units 都有 provenance + jev_validation + anchors_file
4. **证据驱动**——37/116 有真实 MaleCNS 神经元锚定，剩余 79 有明确 `unanchored_reason`
5. **工程质量**——14 门禁全绿，17 个工程配置文件（v2.43.0），Docker/CI/pre-commit 全上

### 不是的地方

1. **Phase 3 自动优化**——原始路线里最核心的一步，已实测为负并明确"不宣称"
2. **计算力/能耗优势**——PROJECT_VISION 里就承认是负，不宣称
3. **涌现行为**——跨单元组合实验（v2.16-v2.20）显示"大多数组合不涌现"，这是**实测结论**，不是宣称
4. **商业化路径**（Phase 4）——完全未启动，¥100-1000/月 是纸面定价
5. **跨物种宽度**——68.1% 单元是跨物种声明（79/116），意味着**大多数单元没有自己物种的锚定数据**，这个宽度是**声明性**的而不是**验证性**的

### 一个诚实的评价

项目 21 天 46 版本，产出：
- 116 单元 + 264 剖面 + 66 连接类型 + 40 motif + 25 blueprint
- 3 连接组 + 1 骨架
- 14 门禁 + 45 MCP tools + 1 CLI + 1 HTTP server + 2 Docker images

**产出密度高**，但产出的**性质**跟最初宣告的不完全一致。原始愿景是"用生物学模式库 + 计算机优化自由度创造超越生物学的形态"，现在实际做的是"**用生物学证据构建可追溯的电路库**"。

这两个方向不矛盾，但**是两件事**。前者是"能力声明"，后者是"知识库建设"。项目现在更偏后者。

## 四、是否已经具备"辅助高效"的能力

**"辅助高效"的定义**：让某个用户（神经科学家 / AI 研究员 / 复杂系统工程师）在某个任务上比"没有这个工具"要快、要准、要少返工。

### 已具备的（可验证）

| 场景 | 能力 | 用户 | 效率提升 |
|---|---|---|---|
| 神经元电路检索 | 116 单元 × 4 属性（system/function/species/provenance） | 神经科学家 | 从"翻 EM 重建论文"到"CLI 一条命令" |
| 跨物种一致性检查 | 同 circuit 在 3 connectome 上的分布 | 比较神经科学家 | 从"手工查三个物种"到"一次查询" |
| 虚拟生物原型设计 | `compose_from_units` + GATE 13 行为学验证 | AI Agent 工程师 | 从"从零搭 agent 拓扑"到"选 N 个已有单元组合" |
| 电路设计合法性检查 | GATE 13 检查孤立节点 + BFS 驱动通路 | Agent 工程师 | 从"跑起来才知道能不能用"到"生成前就知道" |
| 教学示范 | 14 门禁 + 完整 pipeline | 研究生 / 教学 | 从"看 EM 原论文"到"看本项目怎么把 EM 变成可用电路" |

### 不具备的（诚实声明）

| 场景 | 为什么不具备 |
|---|---|
| 证明"AI 能超越生物" | Phase 3 已实测为负，明确不宣称 |
| 通用 Agent Infra | 那是 SwarmLabs 的事，本项目是"生物学先验库" |
| 实时决策延迟 <X ms | 项目不承诺延迟指标 |
| 涌现行为生成 | 跨单元组合实验显示大多数组合不涌现（v2.16-v2.20 已测） |
| 商业化收入 | 无市场验证 |
| 通用 EM 重建 | 不重建神经元，只声明电路；重建是 MaleCNS / Winding / Petkova 的活 |

### 一个精确定位

项目现在的准确定位是：

> **一份有证据的、可组合的、可追溯到 EM 重建的电路库**——不是引擎，不是框架，不是生成器。是一个**给下游用的知识库**，下游可以是 AI Agent 框架（SwarmLabs）、可以是研究、可以是教学。

**"辅助高效"的真实范围**：
- ✅ 让"从 EM 重建到可用电路"这个过程变快（省了重复读论文的时间）
- ✅ 让"跨物种比较同类电路"这件事变快（省了手工比对时间）
- ✅ 让"给 Agent 选初始拓扑"这件事变快（省了从零搭的时间）
- ❌ 不能替代任何 EM 重建工作
- ❌ 不能替代任何 Agent 框架
- ❌ 不能证明任何"超越生物"的性能

## 五、用途分析（按用户分层）

### 短期可用（今天就能用）

**用户 1：神经元电路研究者**
- **场景**：找一个"跨物种都存在的 X 类型电路"作为假说验证起点
- **用法**：`flybrain search --system optic_lobe --cross-species` 返回 9 个单元，跨 4 个物种
- **效率**：从"翻三篇 EM 论文"到"CLI 一条命令 2 秒"
- **价值密度**：高——这是本项目最扎实的场景

**用户 2：Agent 工程师需要生物学先验**
- **场景**：设计一个 Agent 拓扑，不想从零搭
- **用法**：`compose_from_units --units mammal_DEMO` 得到 9 单元组合，GATE 13 已经验证能跑
- **效率**：省了"从零设计 + 手工验证"的时间
- **价值密度**：中——组合空间大，但可组合的合法组合有限

**用户 3：AI/神经科学交叉教学**
- **场景**：教学生"EM 重建 → 电路库 → Agent"的完整 pipeline
- **用法**：本项目作为教科书案例
- **效率**：教学效率极高——项目本身就是教学材料
- **价值密度**：中高——教学材料稀缺，一个能跑得动的开源项目值千金

### 中期有价值（需要生态）

**用户 4：AI Agent 框架开发者**
- **场景**：给主流 Agent 框架（LangGraph/CrewAI/AutoGen）加"生物学先验库"能力
- **用法**：通过 MCP 45 tools 接入
- **效率**：取决于生态，本项目已提供接口，落地要看生态方
- **价值密度**：中——需要有人主动集成

### 长期愿景（未验证）

**用户 5：想要"超越生物学"的 Agent**
- **场景**：设计能"优化任意目标"的虚拟生物
- **现状**：Phase 3 已实测为负，不宣称
- **未来**：需要重新设计 Phase 3 方向，不是本项目当前的路线
- **价值密度**：**待验证**

## 六、诚实总结

### 项目实际是什么

一个**证据驱动的电路知识库**，116 单元 / 3 连接组 / 14 门禁，可追溯到 EM 重建，可通过 MCP / CLI / HTTP 访问。14 门禁保证了它**不会悄悄烂掉**。

### 项目实际不是

不是"超越生物学的 Agent 生成器"（Phase 3 实测为负，明确不宣称）；不是"通用 Agent Infra"（那是 SwarmLabs 的事）；不是"商业化产品"（未启动）。

### 是否如预想在推进

**方向变了，但没有偏离**。PROJECT_VISION 自己承认 Phase 3 不宣称，事实上从 v2.27.0 起主线变成了"证据驱动 + 门禁加固"。这个转变**没有在 CHANGELOG 顶端宣告**，是评估者发现的。建议下一版在 CHANGELOG 顶端加一段"方向转向"声明。

### 是否已具备辅助高效的能力

**具备**，范围明确：
- 神经元电路检索 ✅
- 跨物种一致性检查 ✅
- 虚拟生物原型设计 ✅
- 电路设计合法性检查 ✅
- 教学示范 ✅

**不具备**：
- 证明"超越生物" ❌
- 通用 Agent Infra ❌
- 实时延迟承诺 ❌
- 涌现行为生成 ❌
- 商业化收入 ❌

### 三个建议

1. **在 CHANGELOG 顶端加"方向转向"声明**：从 v2.27.0 起项目主线从"进化速度证明"变成"证据驱动的电路库"，事实如此，让读者一次看清。
2. **把"68.1% 跨物种声明"这个数字写进 README**：116 单元里 79 个是"跨物种声明"（`unanchored_reason` 以 `identity_` / `taxon_` 开头），这不是错误，但**应该明确告知读者**——大多数单元的宽度是声明性不是验证性的。
3. **考虑把"用途"分层写进 README**：短期（可检索/可组合/可教学）+ 中期（AI Agent 先验库）+ 长期（未验证的"超越生物"愿景）。让不同层级的用户各取所需，避免所有人都以为项目是"AI 超越生物的引擎"。
