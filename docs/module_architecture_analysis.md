### 1.2 结构性核心（真实信息流）

三大内在核。自循环有两个口径，含义完全不同，**不要混淆**：

| superclass | 神经元 | 自循环突触 | 占全脑突触 | **占自身输出** |
|---|---|---|---|---|
| `ol_intrinsic` | 89,403 | 35,691,182 | 28.74% | **81.1%** |
| `cb_intrinsic` | 32,164 | 34,365,451 | 27.67% | **87.8%** |
| `vnc_intrinsic` | 13,161 | 11,042,345 | 8.89% | **70.8%** |

- 第一个口径（28.74%）是"占全脑"——合计 65.30%
- **第二个口径才是关键**：这三个核 **70–88% 的输出都回流自身**。它们本质上是三个**自治的递归记忆体**，不是"处理器"。

这是数据直接告诉我们的模块设计原则：**记忆核的主体活动是内部循环，外部输入只占 12–30%。**

**这不是"模块发现"，是"功能命名 + 事后贴标签"。** 真实数据里的 27 个 superclass、146 个 neuropil、8 条自循环、16 个 GABA 门控单元，全都没用上。

### 1.4 正确的做法：功能模块发现算法

"极限最小单位"需要一个可计算的判据。建议三条同时满足：

1. **功能完备**：该单元有独立的 输入 → 变换 → 输出 闭环
   - 数据判据：`in_synapses > 0 AND out_synapses > 0 AND 内部连接密度 > 跨单元密度`
2. **最小可拆**：再拆分就丢失功能
   - 数据判据：内部模块度 Q 最大，且子划分不提升 Q
3. **功能同质**：单元内神经元功能标注一致
   - 数据判据：递质谱熵低（同一单元内递质分布集中）

**流程**：
```
27×27 superclass 连接矩阵（加权有向）
  ↓ 谱聚类 / Louvain（最大化模块度 Q）
候选功能模块
  ↓ 用 146 neuropil 的递质谱做同质性过滤（熵 < 阈值）
最终最小功能单元
  ↓ 与发育/解剖来源交叉验证
数据驱动的模块库
```

**输出应该是**：每个模块带 `real_superclass_ref`（追溯到具体 superclass）、`real_neuropil_ref`（追溯到具体分区）、`measured_io`（真实输入输出突触数）。这才叫溯源的模块库。

### 1.6 跨生物：现在缺什么

你现在只有果蝇。要回答"不同生物是不是有不同功能的模块"，**至少需要第二个完整连接组**：

| 物种 | 神经元数 | 连接组状态 | 可获得性 |
|---|---|---|---|
| 果蝇（已有） | 166,700 | 完整 | ✅ 本地 |
| 线虫 C. elegans | 302 | **完整（经典）** | 公开，体量极小 |
| 斑马鱼幼体 | ~100,000 | 部分 | 公开 |
| 小鼠（MICrONS） | ~200,000 | 1mm³ 皮层 | 公开 |

**线虫是关键**：只有 302 个神经元，却完成了完整的行为闭环。用它做"最小功能单元"的**下界验证**——如果果蝇的 19 个模块里有些在线虫里根本不存在对应结构，那它就不是"跨生物通用最小单位"，而是果蝇特化的。

## 2. 层2：规则与中间件 — 这是"无限延伸"的真正关键

### 2.1 现状

- blueprint：8 个硬编码规则，人工设计
- 嵌套：仅 edge 级 ``"a+(b+c)"`` 语法（union 语义，非真嵌套）
- 中间件：**不存在**
- 乘数/级联语义：**不存在**（边是纯加性连接）

### 2.2 正确的做法：规则要从数据里"反向工程"

真实数据里的 `cross_superclass_top` **本身就是一个模块间连接规则矩阵**：
- 它告诉你**哪些模块连哪些模块**（方向）
- **多强**（突触数）
- **什么频率**（占比）
- **哪些有自反馈**（自循环）

这比 8 个拍脑袋的 blueprint 丰富得多。应该把数据矩阵直接导出为**连接规则表**：

```json
{
  "rule_id": "ol_intrinsic->visual_projection",
  "from_module": "olfactory_memory",
  "to_module": "visual_relay",
  "direction": "feedforward",
  "weight_pct": 6.21,
  "real_synapses": 7714143,
  "source": "MaleCNS v1.0 cross_superclass_top",
  "confidence": "measured"
}
```

### 2.3 要交付给客户的三类资产

| 资产 | 内容 | 形式 |
|---|---|---|
| **模块定义** | 每个最小功能单元的参数（密度/递归率/抑制率） | JSON schema |
| **连接规则** | 数据反向工程的模块间连接表 | JSON + 校验器 |
| **嵌套/叠加标准** | 组合语义、合法性校验、乘数定义 | 规范文档 + 中间件 |

**中间件**（让客户自己组合、自己算）：
- 一个轻量 SDK：只含 模块定义 + 规则表 + 拓扑生成器
- **不含原始神经元数据**（166,700 神经元留在我方）
- 客户本地跑，用自己的算力/存储
- 我方 API 只在"取模块定义"时被调用一次

### 2.4 "乘数"的数学定义（必须现在定清楚）

模块组合的"乘数"有三个层次，**必须分开定义，否则叙事会崩**：

| 层次 | 定义 | 是否真实 |
|---|---|---|
| **组合空间乘数** | N 个模块 → 可能组合数超线性（含数量、变体、连接方式） | ✅ 客观真实，可计算 |
| **结构效应乘数** | 模块组合 → 容错性/可解释性超线性提升 | ⚠️ 部分真实（故障隔离 25/27 是实测的） |
| **性能乘数** | 模块组合 → Agent 任务性能提升 | ❌ **实测为负** |

## 3. 层3：验证 — 现有证据的诚实盘点

### 3.1 实测数据

**MODULE_STACKING 实验**（2 场景 × 5 配置 × 3 轮 = 30 样本）：

| 配置 | 模块数 | score | wall_ms |
|---|---|---|---|
| baseline | 4 | 100.0 | 881–1015 |
| sequential | 4 | 100.0 | 863–979 |
| attention_gate | 6 | 100.0 | 886–942 |
| working_memory_buffer | 6 | 100.0 | 842–915 |
| attention_working_combo | 6 | 100.0 | 858–950 |

**结论：所有配置 score 都 100.0，耗时差异 < 5%。叠加模块没有产生可测量的性能乘数。**

这与此前两个结论一致：
- ESN 计算力：**0/7** 优于随机
- SNN 能耗：**0/24** 优于基线

### 3.2 三种"乘数"的证据状态

| 乘数类型 | 证据 | 可否宣称 |
|---|---|---|
| 组合空间乘数 | 数学上显然（组合数计算） | ✅ 可以 |
| 结构效应乘数 | 故障隔离 25/27 H1（92.6%）实测 | ✅ 可以（限定范围） |
| 性能乘数 | **0/7、0/24、30/30 无差异** | ❌ **不可宣称** |

### 3.3 那么"验证"应该验证什么

既然性能乘数不成立，验证应聚焦**可测且真实**的东西：

1. **结构乘数**：模块组合 → 容错性是否超线性？
   - 可测：单模块故障的传播范围 vs 模块组合的隔离边界
2. **组合空间乘数**：给定 N 个模块，合法组合数曲线的增长
   - 可测：纯数学，确定
3. **可解释性乘数**：模块组合 → 拓扑可追溯性是否提升
   - 可测：PROV 链完整度、溯源深度

**核心原则：验证要验证真实存在的东西，不要为了"乘数"叙事去凑性能数据。** 用户说"是验证过效果的"——那就把"效果"定义在结构层，而不是性能层。

## 4. 防抄袭：核心资产保护

### 4.1 风险

当前仓库 **MIT 全开源**。模块库、聚类参数、规则表全部暴露 → 任何人可复制。

### 4.2 分层保护方案

| 层 | 内容 | 授权 |
|---|---|---|
| **开源薄层** | 接口、JSON schema、中间件的调用约定 | MIT（引流） |
| **闭源厚层** | 模块定义参数、聚类算法参数、规则置信度 | 商业授权 |
| **服务侧** | 原始神经元数据、跨物种配准矩阵 | 仅 API，不落地 |

**三种机制可选**：
1. **API-only**：模块定义不落地，客户通过 API 实时获取（最安全，但需要在线）
2. **加密包**：模块库加密，SDK 内置解密（离线可用，有被破解风险）
3. **水印指纹**：每个客户拿到的模块包带唯一指纹，泄漏可追溯（威慑）

推荐 **API-only 获取 + 指纹水印** 组合。

## 6. 诚实边界

1. **"功能全覆盖"是目标不是现状**：已生成 8 个数据驱动单元（覆盖 99.97% 突触），但粒度只到 superclass 层（27 类）。要真正到"极限最小单位"，需下沉到 neuropil（146）或细胞类型层。
2. **"性能乘数"没有正面证据**：ESN 0/7、SNN 0/24、stacking 30/30 无差异。任何"叠加提效"的宣称都缺少支撑。
3. **跨生物是空白**：只有果蝇。没有第二个物种，就无法回答"哪些模块是通用的"。线虫（302 神经元）是最低成本的下界验证。
4. **"无限"是有边界的**：模块数有限（数据决定）、组合数巨大但非无限。
5. **验证要做成真实可测的**：结构层乘数可测且真实，性能层不成立。
