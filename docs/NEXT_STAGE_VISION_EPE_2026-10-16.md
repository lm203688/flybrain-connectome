## 二、三个改变判断的新事实

### 2.1 C3 rank 标签修正 = 真正结果（B 面从"证伪"回到"有正结果"）

PR-3 v1 用绝对阈值 `drop_magnitude > 0.25` 判定跨图族泛化 → **0/5 族通过（AUC=0.5）**，被记为"机制不具跨族性"。
S7 分辨率预检发现：真实锚点 MaleCNS 子图的 `drop_magnitude` 均值随规模**单调衰减 0.170 → 0.026**，**永远够不到 0.25**——不是机制不存在，是**仪器看不见**。

改用族内秩标签 `label = drop_magnitude > quantile(0.75)`（PR-3 v2，按 R-0.1 记为**新预注册段**而非回改），同一机制：

| 图族 | n=10 | n=20 | n=50 |
|---|---|---|---|
| project_synthetic | 0.913 | 0.867 | 0.733 |
| erdos_renyi | 0.920 | 0.920 | **0.987** |
| barabasi_albert | 0.967 | 0.960 | 0.960 |
| watts_strogatz | **1.000** | 0.760 | 0.893 |
| **malecns_subgraph（真实锚点）** | **0.960** | **0.933** | **0.867** |

**含义**：R1 的"结构→隔离"机制**在 5 个图族（含真实连接组）上全部成立**。这是项目迄今**最强的正结果**，且是"科学空 vs 分辨率失败"二分法的**首个构造性案例**——已写入 P-4 短文。

> ⚠️ **但必须同步收窄**：秩标签是**族内相对量**，它证明"结构能排序族内样本"，**不证明"存在跨族的绝对阈值"**。R1 的口径应从"普适机制"收窄为"**族内可排序、跨族需重标定**"。

### 2.2 C1 cell 级密化 = FAIL（"唯一翻盘实验"已关闭）

| 布局 | n_seeds | mean_score | AUC | n_positive |
|---|---|---|---|---|
| random | 30 | 0.0 | 0.5 | 0 |
| motif | 30 | 0.0 | 0.5 | 0 |
| barabasi | 30 | 0.0 | 0.5 | 0 |

`effect_size = 0.0`。即便把模块内密度提到 0.10（ESN 可用区间），motif 布局**仍不优于随机**。
**含义**：B 面的"计算增益"负结果现在**双重闭合**——模块代表层（0.002–0.023）+ cell 级（0.10）都无增益。**PROJECT_VISION 的最后一条翻盘路径已诚实关闭**，这本身是 P-1 论文的**边界图册条目**（"我们尝试了、并按预注册报告了失败"）。

### 2.3 EPE 原型首跑：装置 ≠ 证据（未记录的缺陷）

本轮新增的 `compute_epistemic_progress.py` 首跑输出：

| claim | apparatus | evidence | gap | 预注册协议 |
|---|---|---|---|---|
| **R1** | **V5** | **E3** | **2** | PR1=WEAK, PR2=FAIL, PR3=FAIL, PR4=PASS, PR2b=ACCEPT, PR3_v2=PASS |
| R2 | V1 | **E0** | 1 | PR5=FAIL |
| R3 | V0 | E0 | 0 | — |
| R4 | V1 | **E0** | 1 | — |
| R5 | V1 | **E0** | 1 | — |
| R6 | V0 | E0 | 0 | — |

**三个发现**：

1. **R1 装置 V5 / 证据 E3**——挂着"最高级验证徽章"，但其 6 条预注册协议中 **2 条 FAIL、1 条 WEAK**。徽章与证据脱钩。
2. **R2/R4/R5 状态为 `verified`/`complete`，证据却是 E0**——它们**没有任何预注册协议**，是"由描述性产物 + 自测"支撑的，不是"由预注册测试"支撑的。这不是错误，但**徽章把它们与"经过预注册检验"混为一谈**。
3. **阶梯 V1–V5 的谓词与其名称全部不符**（§九）：
   - V1 名称"reproducible（同 seed 逐位一致）"，谓词却是"≥1 条证据边"——**不检查复现性**；
   - V5 名称"externally verified（外部验证）"，谓词却是"收据存在 + 红队标志"——**收据是哈希承诺，不含外部方**；且 `redteam_passed` 是**一个全局 CLI 布尔**，不是逐主张计算。

> **这是本项目第 4 次遇到"度量不测其所声称之物"**（前三次：S6 对照组可得分性、S7 分辨率钳位、PR-2b 解析冗余）。**前三次是抓别人/抓自己的实验，这一次是抓自己的验证层本身。** 它恰好证明：VRO 缺一个"**进度信号是否真的度量进度**"的自检——这就是 EPE 的 E1。

## 四、下一阶段愿景：认知进度引擎（EPE）

### 4.1 愿景陈述

> **把项目从「一个诚实、可验证、但不产生方向的私仓工具」，升级为「一个把验证转化为方向的引擎」：每一条主张不仅携带"验证装置"与"证据强度"两个可读的轴，还携带一个稠密、受保护的认知进度信号；该信号决定下一个实验；被证伪与未被走的路径沉淀为可引用的边界图册。**

一句话区分**市场现状**与**本项目愿景**：

| | 市场/前沿现状（2026-10）| 本项目下一阶段愿景（EPE）|
|---|---|---|
| 信号 | 二值裁决（PASS/FAIL），稀疏 | **稠密进度向量 + 双轴（装置 / 证据）** |
| 方向 | 人工排期实验 | **信号→下一步实验（反馈导向搜索）** |
| 验证 | 事后统计，可被自适应复用 | **holdout 保险库：提交先行、一次性开箱** |
| 失败 | 沉没、不可引用 | **边界图册：一等产出、可交叉验证** |
| 采纳 | 每个实验室自建 | **独立可安装协议（`selfverify` 已起步）** |

### 4.2 五层架构（VRO → EPE）

```
L5  采纳层         ← 独立可安装协议 + 边界图册对外可引用                    【本轮起步】
L4  进度信号层     ← 稠密认知进度向量（装置轴 × 证据轴 + 覆盖）             【本轮原型 ✅】
L3  受保护验证层   ← holdout 保险库：提交先行 + 一次性开箱 + 防复用          【缺】
L2  对抗自验证层   ← 红队 + 收据 + 预执行拒绝注册表                        【已有】
L1  命题图层       ← 类型化命题图 + 状态阶梯                              【已有】
```

**护城河**：L1+L2 已是国际前列（VRO 全栈）；**L3+L4 是"从诚实到有方向"的关键一跃**，且市场刚刚（2026-08）才提出这个需求。

## 五、执行方案（E / S / M 三阶段）

> 原则：**E 阶段（引擎）为主线**——零/低成本、把已有组件连成回路；**S 阶段（科学）为巩固线**——把 C3 正结果与 C1 负结果诚实入册；**M 阶段（采纳）为壁垒线**——把协议做成别人能用的东西。

### E 阶段 — 认知进度引擎（主线）

#### E1 稠密认知进度信号（双轴分离）★ 本轮已落地原型
- **做什么**：把单一 V0–V5 徽章**拆成两条轴**：**A 轴（装置）** = 现有徽章；**E 轴（证据）** = 由预注册协议的 `tier × verdict` 计算。输出 `progress.json`。
- **为什么**：直接暴露"装置 ≠ 证据"（§二.3）；这是 2608.09855 要求的"稠密进度信号"的最小实现。
- **具体操作（本轮已落地）**：
  ```bash
  "C:/Python314/python.exe" scripts/compute_epistemic_progress.py
  # -> progress.json (双轴) + boundary_atlas.json (7 条边界)
  ```
- **验收**：`progress.json` 每条 claim 含 `apparatus` / `evidence` / `gap`；`gap ≥ 2` 的主张被显式列为 `divergent_claims`。**已达成：`divergent_claims = ["R1"]`**。
- **下一步（E1b）**：把徽章阶梯的**谓词改成与其名称相符**（V1 真查复现性、V5 真查逐主张红队），并加 **Gate 54「度量语义一致性」**：断言每个阶梯级的谓词测试其命名属性（本轮审计已给出 mismatch 清单，§九）。

#### E2 反馈导向实验调度（signal → next experiment）
- **做什么**：读 `progress.json` + `boundary_atlas.json`，按**信息增益**排序候选实验，输出"下一个该跑什么"。类比 fuzzer 的 coverage-guided mutation：**coverage = 边界图册的覆盖**。
- **为什么**：这是 2608.09855 的第二个能力——"信号必须决定下一个干预，使 agent **搜索**而非**重复采样**"。
- **具体操作**：`scripts/next_experiment.py` → `next_experiment.json`（候选实验 + 预估信息增益 + 依据的边界条目）。
- **验收**：给定当前状态，脚本能指出**最高信息增益**的实验（例如"PR-3 v2 已在 5 族通过 → 下一步应做**跨族绝对阈值的重标定实验**，而非再跑同族扩样"）。

#### E3 受保护验证（holdout 保险库）★ 最高价值
- **做什么**：**提交先行、一次性开箱**。对每个预注册协议，在跑实验**之前**把 (i) 判据、(ii) 数据生成种子、(iii) 期望区间 提交到一个**内容寻址保险库**（`vault/<protocol>.commit.json`，含 salt+hash）；实验完成后**一次性**开箱比对，**开箱后不得再改判据**。
- **为什么**：直接实现 2608.09855 的第三个要求"**证据受保护、免于自适应复用**"。**C3 的 rank 标签修正虽然是合法的 R-0.1 新段，但恰好说明"看到结果后改标签"的诱惑真实存在**——保险库把它变成机器纪律。
- **具体操作**：`scripts/vault.py commit|open|verify`；**Gate 55「holdout 完整性」**（每个 PASS 协议必须有先行 commit；开箱次数 ≤ 1）。
- **验收**：对一条协议，篡改 `expected_verdict` 后 `vault verify` 报 `MISMATCH`；未先行 commit 的协议被 Gate 55 拒绝。

#### E4 边界图册产品化（durable negative knowledge）
- **做什么**：把 `boundary_atlas.json` 升级为**可引用资产**：每条含 (claim, tier, verdict, 证据文件 hash, 未走路径, 复算命令)，并导出为 **RO-Crate + nanopublication**（签名、机器可读）。
- **为什么**：直接对接"Negative Knowledge"前沿——**失败要成为持久、可共享的知识资产**。
- **验收**：`boundary_atlas.json` 每条可被独立重算脚本复现；导出包通过 RO-Crate 校验。

#### E5 验证器在环 agent（可选，E1–E4 成型后）
