## 一、前沿扫描：五条线，逐条给证据

### 1.1 多智能体结构线 —— 最关键的一条

**AdaptOrch**（arXiv:2602.16873，2026-02-18，21 页，作者 Geunbin Yu）

| 项 | 内容 |
|---|---|
| 核心论断（原文） | "**orchestration topology — the structural composition of how multiple agents are coordinated, parallelized, and synthesized — now dominates system-level performance over individual model capability**" |
| 提出 | **Performance Convergence Scaling Law**：形式化了"编排选择胜过模型选择"的条件 |
| 方法 | Topology Routing Algorithm：把任务分解 DAG 映射到最优编排模式，O(\|V\|+\|E\|) |
| 结构空间 | **仅 4 种 canonical 拓扑**：parallel / sequential / hierarchical / hybrid |
| 结果 | **同样模型下，仅改编排结构即提升 12–23%**（SWE-bench / GPQA / RAG） |
| 诚实标注 | **单作者预印本**，未见顶会录用记录。数字方向性强，但**作为单一来源需谨慎** |

**这条线对本项目的分量最重**：它是 2026 年唯一一条**直接、量化地**证明"结构 > 模型"的工作。

### 1.2 自进化 / 自我改进线

| 工作 | 时间 | 要点 |
|---|---|---|
| **A Survey of Self-Evolving Agents**（TMLR 2026） | 2026 | 首篇系统综述，沿 **What / When / How / Where** 四维度组织（演化什么、何时演化、如何演化、在哪评估） |
| **Darwin Gödel Machine**（ICLR 2026） | 2026 | 开放式自我改进；维护历史智能体库，把"有趣但非最优"的解当作垫脚石 |
| **SkillOpt-Lite / HarnessOpt**（arXiv:2607.03451） | 2026-07 | 微软参与；四步循环（轨迹存盘 → 翻日志 → 共识挖掘 → 独立验证门控）；**"能力倒置"**：小模型在优化 harness 里 0.7758 > 大模型在次优 harness 里 0.7620 |

**共同点**：三者的"验证"环节都是**任务指标**（准确率/通过率），**没有一个是结构性健康度量**。

### 1.3 人工生命 / 涌现线 —— 你给的线索在这条线里

| 工作 | 时间 | 要点 |
|---|---|---|
| **Computational Life**（arXiv:2406.19108，**Google** + UChicago） | **2024-06**（**两年前**） | BFF 基底（指令带=数据带），随机 64 字节带，**无显式适应度**，~40–50% 涌现出自我复制器；**SUBLEQ 反例**：可手抄 60 字节复制器但随机汤数十亿次不涌现 |
| **Directing Open-Ended Evolution via Multi-Scale Path Divergence** | **2026-06** | 明确指出 OEE 常由**不可解释的黑盒神经网络**驱动，提出多尺度路径分歧来"引导"——**即"可解释性"已成为 OEE 的前沿议题** |
| **Neural Cellular Automata 综述**（arXiv:2509.11131 / 2026-03 期刊版 / 2026-07） | 2025-09 起 | NCA 作为生物启发的自组织/形态发生模型持续活跃 |

**对这条线的诚实评估**：
- 你给的谷歌实验是**真实的、有分量的**，但它是 **2024 年**的，且**论文自身声明**：这是计算模型、**不是生物起源的证据**；哪些基底允许涌现**仍是开放问题**
- **2026 年这条线已经往前走了**：从"能不能涌现"（2024）转向"**涌现出来后怎么引导、怎么解释**"（2026 OEE 可解释性工作）
- **因此它不能单独支撑一次方向重构**，只能作为三条结构来源之一（见 §二）

## 二、扫描得出的四个判断（本报告的核心）

### 判断 1：2026 主线已从"模型"转向"结构 + 演化"——四条独立证据

| 证据 | 来源 | 指向 |
|---|---|---|
| 模型性能收敛，编排拓扑主导系统性能（12–23%） | AdaptOrch 2026-02 | **结构 > 模型** |
| 自我改进成为 Agent 范式 | TMLR 2026 survey + DGM (ICLR 2026) | **演化 是主线** |
| 小模型在优化 harness 里打赢大模型 | SkillOpt-Lite 2026-07 | **环境 > 模型** |
| 安全保证移向容纳/边界层 | Containment Verification 2026-05 | **边界 是治理位** |

> **四者互不相干、时间集中在 2026 年，指向同一件事：竞争焦点是"系统如何组织与演化"。**
> **本项目过去八个月做的全是"结构"。它站在主线上，只是自己没认出来。**

### 判断 2：本项目最痛的负结果（0/7），可能测错了基底 —— 这是最高价值的未测实验

| | 本项目 0/7 | AdaptOrch 12–23% |
|---|---|---|
| 基底 | **ESN 储备池**，模块代表层，**密度仅 0.002–0.023** | **LLM 多智能体编排** |
| 任务 | 合成序列记忆任务 | SWE-bench / GPQA / RAG（真实任务） |
| 结构来源 | 生物 motif vs 随机结构 | 4 种 canonical 拓扑 vs 固定单一拓扑 |

**两条并不矛盾**——它们测的是不同基底。**但由此浮出一个从未被测过的问题：**

> **把本项目的 25 个蓝图 / 116 单元组合出的结构，作为 LLM Agent 的编排拓扑，
> 与「随机结构」和「AdaptOrch 的 4 种 canonical 拓扑」对照，谁更强？**

- 若**胜**：0/7 得到解释（基底问题，不是结构无效），本项目一举接上 2026 主线
- 若**负**：是第 4 条负结果，**诚实发布**——但这次是在**正确的基底**上测的，终于能真正结案

**这个实验同时是本项目"结构有效性"问题的唯一正解。** 它比任何定位文档都重要。

### 判断 3：前沿的"结构空间"极其简陋，本项目是数量级优势——但从没被放到前沿语境里用

| | 结构空间规模 | 证据来源 | 可追溯 | 结构健康度量 |
|---|---|---|---|---|
| **AdaptOrch** | **4 种** | 无（工程约定） | 无 | 无 |
| **TMLR survey / DGM** | 未形式化结构空间 | 无 | 无 | 无 |
| **谷歌原始汤** | 自发涌现，不可枚举 | 无 | 无 | 无（只有代理熵指标） |
| **本项目** | **116 单元 × 66 连接类型 × 83 端口 × 25 蓝图 × 12+7+4 规则** | **真实连接组（MaleCNS / 线虫 / 幼虫 / 斑马鱼）** | **W3C PROV-JSON 三段溯源** | **故障隔离 92.6%（25/27）+ 拓扑体检** |

> **本项目的结构空间比前沿大几个数量级，且唯一带证据来源。**
> **但它从未被当作"给 Agent 系统用的结构库"来交付——它被当作"虚拟生物形态生成器"来交付。**
> **这是定位问题，不是能力问题。**

### 判断 4：前沿缺"结构退化"的度量，而这恰是本项目唯一的硬结果

自进化系统的核心风险是**"改坏了不知道"**。2026 的三条治理工作（Containment / AI Control / 递归自我改进）
都在找"怎么判断系统变坏了"。它们找的是**边界与监控**，而本项目手里有**结构性度量**：

- **模块级故障隔离 25/27 = 92.6%**，效应量中位 Δ28 pp（最大 39.7 pp）
- **拓扑体检**：谱半径 ρ / 反馈边比例 / 模块度 Q / 有向 3 节点模体 / 结构签名 sha256（可复算）
- **24 道 fail-closed 门禁**（每道都做过"注入缺陷证明会报红"）

> **"改完以后结构有没有退化"——这个度量，2026 前沿没有任何人有。**

## 三、定位（由上述四个判断推出）

### 3.1 三种"结构从哪来"的答案，本项目是第三种

| 派别 | 代表 | 结构从哪来 | 规模 | 有证据吗 | 会退化吗 |
|---|---|---|---|---|---|
| **涌现派** | 谷歌 Computational Life (2024)、OEE (2026) | 自己长出来 | 不可枚举 | 无 | 不知道 |
| **路由派** | AdaptOrch (2026) | 从 **4 种**里按任务选 | **4** | 无 | 不知道 |
| **证据派（本项目）** | flybrain-connectome | **从真实连接组继承，可组合、可验证** | **116×66×83** | **有（PROV-JSON）** | **可测（92.6%）** |

**三派不互斥**：涌现派解决"从无到有"，路由派解决"按任务选"，证据派解决"**来路正不正、会不会坏**"。
**前两派都不管第三个问题——而这个问题在自进化系统里要命。**

### 3.2 新定位

> **flybrain-connectome = 可验证结构的供给与治理层（Verifiable Structure Layer）**
>
> 为自进化 / 自适应的 Agent 系统提供：
> 1. **一个有证据来源的结构空间**（116 单元 / 66 连接 / 83 端口 / 25 蓝图 / T3 规则）——远超前沿的 4 种；
> 2. **一套结构退化的度量**（故障隔离 92.6% + 拓扑体检 + 结构签名）——前沿完全没有；
> 3. **一条可追溯的血统**（W3C PROV-JSON 三段溯源）——回答"这个结构来自哪个神经元"。

### 3.3 "数字生命"在这个定位里的位置（回答你最初的关切）

**数字生命是本项目的一个可能应用场景，不是定位本身。**

- 若走涌现路线（谷歌那条），本项目提供的是**"汤"的观测与治理**——但这是**期权，不是主投**
- 若走自进化路线（TMLR/DGM/HarnessOpt 那条），本项目提供的是**结构退化度量**——**这是主投，因为它有 92.6% 这个已测数字撑腰**
- **定位写"可验证结构层"而不是"数字生命"**，因为前者有实测支撑，后者目前只有别人 2024 年的实验

### 3.4 与旧定位的关系

| 旧 | 新 | 变化性质 |
|---|---|---|
| 虚拟生物形态生成器 | 可验证结构的供给与治理层 | **换评价框架**（不再用"超越生物学"，改用"结构有效性 + 可验证性"） |
| 已证伪三条（0/7、0/24、涌现） | 仍不宣称；但 0/7 被识别为**可能测错基底** | **不是翻案，是定位测错的可能** |
| 116 单元等资产 | 全部保留，但**交付对象**从"虚拟生物"改为"Agent 系统" | **资产不浪费，只换用途** |

## 四、路线：P1–P4（按"前沿缺口 × 本项目优势"排序）

### P1 · 把结构空间接到 LLM 编排基底上做对照实验 —— **最高价值，唯一能真正结案的实验**

| 项 | 内容 |
|---|---|
| 做什么 | 用本项目的 25 蓝图 / 单元组合作为 **LLM Agent 的编排拓扑**，对照 **① 随机结构 ② AdaptOrch 的 4 种 canonical 拓扑**，在真实任务上测 |
| 回答什么 | 本项目的结构在**正确基底**上到底有没有效？（0/7 是基底问题还是结构无效？） |
| 验收 | 有脚本 + 有数字 + 有门禁；**胜则接主线，负则作为第 4 条负结果诚实发布** |
| **依赖** | **需要 LLM 访问**（API 或本地模型）——这是本项目**唯一的新外部依赖**，需你确认可行性 |
| 为什么第一 | 它直接决定本项目"结构"这件事值不值钱。定位文档写得再好，也替代不了这个数字 |

### P2 · 结构退化度量产品化

把故障隔离 + 拓扑体检 + 结构签名封装为**对外可用的"结构体检 API"**：改前/改后各测一次，退化即拒。
**这是 §二 判断 4 的直接兑现，且零外部依赖。**

### P3 · 吸收"性别二态性"证据维度（低成本增量）

**已核实：数据版本无需升级**（v1.0 即 2026-09 完整版）。
真正的增量是：官方新发现的 **262 个雄性专有细胞类型 + 114 个两性差异型细胞类型**，
本项目**尚未作为证据维度使用**（当前只用 superclass 27 + 神经递质）。

| 交付 | 验收 |
|---|---|
| P3.1 评估该维度能否提升 **37/116** 的锚定率 | 有数字；若提升则入库，若无提升则**显式记录无提升** |
| P3.2 评估是否值得作为**新证据轴**（跨物种单元所没有的真实证据） | 有对照说明；不夸大 |

### P4 · 涌现路线作为期权（小规模，不主投）

若仍想探索谷歌那条线：**只做 S1 最小汤原型**（独立原型，不耦合 organism schema v1.2.1），
设**明确的止损条件**（N epoch 无涌现即发布负结果并停止）。
**理由**：它是 2024 年结果，且论文自陈"哪些基底允许涌现仍是开放问题"——**不值得主投**。

## 五、诚实边界

1. **本报告的外部证据以预印本与二手解读为主**：AdaptOrch（**单作者预印本**）、DGM（ICLR 2026）、
   TMLR survey、Containment Verification 等，**均未逐篇核对原文表格**。方向性可用，**具体数字对外引用前须核对原文**。
2. **谷歌 Computational Life 是 2024 年**的，论文自陈：这是计算模型，**不是生物起源证据**；
   哪些基底允许涌现**仍是开放问题**。它在本报告中只是五条线之一。
3. **本项目从未在 LLM 编排基底上测过自己的结构。** P1 是**待验项**，不是既有成果。
   **0/7 依然是本项目在 ESN 基底上的有效结论，本报告不是翻案，只是识别出"可能测错了基底"。**
4. **不宣称计算力 / 能耗优势**（0/7、0/24 实测为负）。新定位走的是"结构有效性 + 可验证性"轴，**不重开这两条**。
5. **92.6% 故障隔离是结构属性度量，不是任务性能**——它说"关一个模块其他掉得少"，不是"任务做得更好"。
6. **68.1% 单元的宽度是声明性的**：79/116 是跨物种声明，不是 MaleCNS 锚定。
7. **T3 已本地解锁但裸公开安装下 Gate 24 会跳过**——对外部用户规则层仍不可得。
