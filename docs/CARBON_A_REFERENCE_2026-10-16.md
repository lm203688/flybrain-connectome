# Carbon-A 方法学参考 memo（2026-10-16 · v0.1）

**结论**：Carbon-A 是本项目的**方法学邻居，不是竞品**。它把大模型用在**跨谱系基因注释**这个"数据极度不均 + 标签稀缺"的任务上，用四条工程纪律把 1.2B 参数模型跑成了可发表的科学工具。这四条纪律里有两条可以直接迁移到我们项目的**跨图族泛化**与**度量族扩展**问题，另外两条是**认识论层面的提醒**。

---

## 一、Carbon-A 速览（HuggingFaceBio · 2026）

| 项 | 值 |
|---|---|
| 模型 | Carbon-A，1.2B 参数 DNA gene annotation 模型 |
| 基底 | 基于 GENERator 系列（DNA 基础模型） |
| 上下文 | 98,304 bp（约 100 kb，覆盖多数真核基因的完整转录单元） |
| 训练集规模 | 566M candidate genes，跨 22,617 taxa |
| 主指标 | **F1 = 0.944**（gene call vs. annotated gene） |
| 置信度校准 | **AUROC = 0.876**（预测概率 vs. ground truth 排序） |
| 独立验证 | PacBio Iso-Seq wet-lab，跨物种验证 |
| 许可证 | 模型权重 CC-BY-NC-SA，代码 Apache-2.0 |
| 定位 | **跨谱系迁移学习**（cross-lineage transfer）代表工作 |

**与本项目的对照**：本项目用 MaleCNS v1.0（166,700 neurons, 124M synapses）做**单谱系拓扑生成 + 度量族评估**；Carbon-A 用 566M 基因、22,617 物种做**跨谱系基因注释**。规模相近（都在百万级数据点量级），但任务性质不同：Carbon-A 是**分类/注释**（有明确标签），本项目是**结构度量/因果干预**（度量族本身是待建立对象）。

## 二、四条方法学参考点

### 参考点 1：**跨谱系迁移**（Cross-Lineage Transfer）→ 对应本项目"跨图族泛化"（PR-3）

**Carbon-A 做法**：在 22,617 taxa 上训练，测试时零样本迁移到未见过的物种；标签稀缺物种（如某些真菌/古菌）仍能保持可用 F1。

**对应本项目问题**：`PR-3 泛化到 5 图族 FAIL`——2/5 图族（无真实锚点），根因是**标签分辨率不是模型**（`malecns_subgraph` 四档规模 n_positive 全 0）。

**可迁移实践**：
- **Carbon-A 用"多数谱系有标签 + 少数谱系零样本"的方式绕开了每谱系都要标注的问题**。本项目目前的做法是"每个图族独立评估"，导致小图族（如 `malecns_subgraph` 的 4 档规模）直接失败。
- **建议**：把 `drop_magnitude` 的**绝对阈值 0.25** 改为**相对分位标签**（如每图族 top-10% 定义为 positive），或者用 Carbon-A 的"跨谱系共享特征空间"思路——在 motif_family 上先学到"什么是重要扰动"，再迁移到 malecns_subgraph。
- **代价**：需要重新跑 PR-3（v2），但根因已经被 v1 FAIL 定位到"标签分辨率"，改动方向明确。

**迁移风险**：Carbon-A 的任务是分类，本项目是干预效应度量，"分位标签"是否仍能让干预效应可比较是**未验证假设**，需要预注册。

---

### 参考点 2：**版本鲁棒性**（Version Robustness）→ 对应本项目"度量族漂移"

**Carbon-A 做法**：模型权重、评估脚本、ground-truth 数据集三者**独立版本化**；每次发布时三者版本锁定为兼容三元组；跨版本迁移需要显式声明（如 "Carbon-A v0.3 weights on v0.1 ground-truth" 是不支持的组合）。

**对应本项目问题**：本项目 51 门禁 + 5 条预注册协议（PR-1/2/2b/3/4）目前都是**代码内的隐式版本**，没有独立的"度量族版本号"。当 `drop_magnitude` 的定义从"绝对值"改成"分位值"时，历史结果不可比。

**可迁移实践**：
- **建议**：新增 `registry/metric_family_versions.json`，把每个度量（`drop_magnitude`, `bridge_fraction`, `recovery_AUC` 等）的**定义、阈值、计算脚本 hash** 都版本化；每次预注册协议必须声明它用的度量族版本；每次结果产物必须声明它基于哪个度量族版本。
- **门禁扩展**：Gate 48（新）检查"每个预注册协议的度量族版本声明存在且与当前代码一致"。
- **论文价值**：这是 R-0.2 机器固化纪律的**度量族级延伸**——目前 R-0.2 只管阈值/特征集/种子，不管度量定义本身。

**迁移风险**：需要重构度量计算层，工作量中等；但不做的话，未来"度量定义演进"时历史结果会静默失效。

---

### 参考点 3：**独立湿实验验证**（Wet-Lab Independent Validation）→ 对应本项目"L4 基底上限"

**Carbon-A 做法**：模型预测的基因调用用 **PacBio Iso-Seq 全长测序**独立验证——湿实验完全不依赖模型训练数据，是真正的**正交证据**。

**对应本项目问题**：本项目的"验证"全部是**同一度量族内的内部一致性**（Gate 30 检查 S6-S9、Gate 43-47 检查预注册一致性）——都是**同一计算基底内的自证**。PR-2b 已经证明这个基底有上限（"现有度量族内没有独立的第二读数"）。

**可迁移实践**：
- **本项目能做的"湿实验等价物"**：找一个**不由本项目度量族派生的独立信号**作为外部锚点。例如：
  - **flywire 仿真验证**（已有项目，用 MaleCNS 拓扑驱动神经仿真，检查仿真行为是否与本项目预测的关键边一致）——本项目已在论文 §5.4 提及但没做；
  - **跨项目交叉引用**（如 Janelia 的 connectomics 团队对 MaleCNS 的独立分析、KAIST 的任务增益报告）——作为**外部锚点**而非本项目度量族的一部分。
- **论文价值**：把"L4 基底上限"从"承认做不到"升级为"我们尝试过 X 个正交锚点，Y 个不可得，Z 个已做"——**诚实的边界刻画比"我们做不到"更有信息量**。

**迁移风险**：flywire 仿真需要 GPU 算力 + 时间（用户口头提到的 RTX 3090/4090 在另一台主机），不是本轮能做的工作。

---

### 参考点 4：**置信度校准**（Confidence Calibration）→ 对应本项目"预测强度分级"

**Carbon-A 做法**：不仅报 F1（分类准确度），还报 **AUROC = 0.876**（预测概率对 ground truth 的排序能力）——即"模型知道自己多不确定"。

**对应本项目问题**：本项目的"WEAK / FAIL / PASS / REJECT-BEFORE-RUN"四态是**离散判定**，没有连续的置信度。PR-1 的 WEAK（AUC 0.788 但 z=1.53）是"部分通过"，但没有连续的置信度可以排序多个 WEAK 结果。

**可迁移实践**：
- **建议**：在每个预注册协议的结果中新增 `confidence_score`（0-1），定义为：
  - `confidence = P(metric crosses threshold | preregistered protocol)` 通过 bootstrap 或 permutation 估计；
  - 或更简单：`confidence = min(P_primary, P_secondary)`，两个分量都过阈才高置信。
- **门禁扩展**：Gate 49（新）检查"每个预注册协议的 confidence_score 声明存在"。
- **论文价值**：把 WEAK 从"部分通过"升级为"可排序的部分通过"——两个 WEAK 可以比较谁更接近 PASS。

**迁移风险**：需要重新跑 PR-1/2/3 的置信度估计（零依赖，纯计算）；但结果本身不会改变（FAIL 还是 FAIL，PASS 还是 PASS），只是加了连续强度。

## 三、四条参考点的可迁移性矩阵

| 参考点 | 对应本项目问题 | 迁移难度 | 预期收益 | 建议优先级 |
|---|---|---|---|---|
| 1. 跨谱系迁移 → 跨图族泛化 | PR-3 FAIL 的根因 | 中（需重跑 PR-3 v2） | 高（可能翻转 PR-3 到 PASS） | **P1** |
| 2. 版本鲁棒性 → 度量族漂移 | 隐式版本化问题 | 中（需新增 registry + Gate 48） | 中（防御性，非直接产出） | **P2** |
| 3. 湿实验验证 → L4 基底上限 | PR-2b 的结构性缺口 | 高（需 flywire 或外部锚点） | 高（可能突破基底上限） | **P3**（等 GPU） |
| 4. 置信度校准 → 预测强度分级 | WEAK 无法排序 | 低（纯计算，零依赖） | 低-中（改进表述，不翻转结果） | **P4** |

**优先级排序依据**：
- **P1（跨图族泛化）**：直接对应 PR-3 的 FAIL 根因，可能翻转结果，是论文素材的直接增量；
- **P2（版本鲁棒性）**：防御性工程，不做的话未来会有历史结果失效风险；
- **P3（湿实验验证）**：唯一能突破 L4 基底上限的路径，但需要外部算力；
- **P4（置信度校准）**：最低成本，但收益也最低——不改判定，只加强度。

**建议顺序**：P1 → P4 → P2 → P3（P3 等算力可用再做）。

## 四、不迁移的部分（诚实边界）

Carbon-A 有四条方法学实践是**本项目不适合迁移的**：

1. **大模型基底（1.2B 参数）**：本项目的"基底"是 MaleCNS v1.0 拓扑 + 度量族，不是神经网络参数。用大模型"重构"拓扑生成器会重演 PR-2b 教训——用不成立的度量替代真缺口。
2. **98,304 bp 上下文**：对应本项目的"完整拓扑"是 166,700 neurons × 124M synapses，量级完全不同，不需要长上下文。
3. **CC-BY-NC-SA 许可证**：本项目是 MIT + CC-BY 组合，不适合改（会限制商用可能性）。
4. **PacBio Iso-Seq 湿实验**：本项目的等价物是仿真验证，不是真正的湿实验（本项目是计算方法学项目，不是实验生物学项目）。

## 五、与 P-4/P-5 短文的关系

- **P-4（PR-2b 短文）**：Carbon-A 的"湿实验验证"是 PR-2b 的"基底上限"结论的**对照案例**——PR-2b 说"本项目的度量族内没有独立第二读数"，Carbon-A 说"我们用 PacBio Iso-Seq 找到了独立第二读数"。两条路都成立，但本项目**没有湿实验资源**，所以只能走"承认基底上限"。
- **P-5（S6-S9 短文）**：Carbon-A 的四条纪律可以并入 S6-S9 的**扩展清单**（S10-S13），但需要先在论文 §4.9 后新增一节说明"参考但迁移有限"。

## 七、一句话总结

**Carbon-A 是本项目的"方法学邻居"，不是竞品。它的四条纪律（跨谱系迁移、版本鲁棒性、湿实验验证、置信度校准）中，"跨谱系迁移"和"版本鲁棒性"可以直接迁移，"湿实验验证"是唯一能突破 L4 基底上限的路径但需要外部算力，"置信度校准"成本最低收益也最低。建议按 P1（跨图族泛化重跑）→ P4（置信度校准）→ P2（版本鲁棒性）→ P3（湿实验等价物）顺序推进。**
