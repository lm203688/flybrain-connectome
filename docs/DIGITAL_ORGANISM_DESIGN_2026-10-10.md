## 让虚拟生物具备自我修复、演化、组合创新与进化的能力，并接入 2026 前沿技术

**日期**：2026-10-10

## 〇、目标与现状

### 目标：四条数字生命特征

| 特征 | 具体含义 | 今天有没有 |
|---|---|---|
| **自我修复** | 受损后能回到损伤前的结构/功能状态，且**能证明没退化** | ❌ 0 |
| **演化** | 代际之间发生**可度量**的改变 | ❌ 0 |
| **组合出新东西** | 两个个体组合后，产生**任一亲代都不具备的可测能力** | ❌ 0（只能拼，不能判"新"） |
| **进化** | 在选择压下种群逐代适应 | ❌ 0（GA 是离线一次性搜索，8/8 输随机） |

### 现状的一句话

> **今天 `flybrain generate` 产出的是一个带 `generated_utc` 的静态 JSON——
> 它有器官、有血管、有出生证明，但它没有心跳。**
> **本方案要做的，就是给它装上一套生命循环。**

## 一、总体架构：虚拟生物生命循环（8 阶段）

```
   ① 出生 Birth ── 蓝图 + 单元组合 → organism（带 PROV 血统）
        │
        ▼
   ② 存活 Live ──── 代谢循环：输入 → 状态更新 → 输出
        │            ├─ 持续监护（拓扑体检：ρ / 反馈边 / 模块度 / 结构签名）
        │            └─ 应激（北极星 D1：t≤k 步不经全局读出直接响应）
        ▼
   ③ 受损 Damage ── 扰动注入：模块失效 / 接线断裂 / 端口污染
        │
        ▼
   ④ 自愈 Repair ── 检测 → 最小补丁 → 独立验证 → 接受 或 回滚
        │
        ▼
   ⑤ 繁殖 Reproduce ─ clone + mutate(原子补丁) → 后代（继承血统）
        │
        ▼
   ⑥ 选择 Select ─── 存活判据（**不是 fitness**）→ 谁留种
        │
        ▼
   ⑦ 死亡 Death ──── 终止判据 → 血统封存 + 资源回收
        │
        └──────────────→ 回到 ②
```

**每一环对应一个可测判据，每一环配一条门禁。** 这是本项目既有的纪律，不做例外。

## 二、五个核心设计（这是「结合出新东西」的实质）

### D1 · 结构即可写对象（Structure-as-Writable）

**问题**：今天 organism 是只读快照，接线不能被运行过程改变 → 原理上不可能自愈、不可能演化。

**设计**：把 organism 从"JSON 产物"改造成**一个可写的结构对象**，其接线可被自身运行修改。

| 项 | 内容 |
|---|---|
| **2026 技术来源** | 谷歌《Computational Life》（arXiv:2406.19108）的核心机制：**指令带 = 数据带**，执行可改写自身代码 |
| **本项目的加强** | 谷歌的汤**没有任何边界**。**本项目只允许通过 83 个 typed 端口写入，越界即拒并记录** |
| **本项目资产** | 83 个类型化端口（`cortex.input` 这类层级类型）+ 66 连接类型（定义了 `from_port → to_port` 合法映射）+ 端口兼容矩阵（500 对可连 / 61 对不兼容已登记） |
| **验收** | 注入越界写入 → 运行时拒绝 + 门禁报红 |

> **这是本项目比谷歌强的地方**：谷歌证明了"可自修改 → 涌现"，但他们的涌现**不可控、不可读**。
> 本项目在 typed 端口下做自修改，**每一次修改都是可读、可判定合法性的**。

---

### D2 · 修复算子：三种原子补丁 + 结构性验收

**问题**："重新生成一个更好的"不算自愈；自愈必须是**针对损伤的最小修复**。

**设计**：

| 补丁 | 语义 |
|---|---|
| `add_unit` | 在指定位置插入一个功能单元（须满足端口兼容） |
| `rewire` | 改动一条边的 from/to（须满足连接类型的 `from_port → to_port`） |
| `drop_unit` | 移除一个单元并修补悬空边 |

**修复循环**（四步，移植 SkillOpt-Lite）：

```
① 轨迹暂存   运行轨迹逐条存盘（含监护指标）
② 轨迹探索   按失败类型归类，挑少数重点读（不是全塞进上下文）
③ 共识挖掘   找跨任务/跨损伤的共同失败模式 → 生成**最小**补丁
④ 验证门控   独立验证集评估 + **结构性验收** → 接受 或 git 回滚
```

| 项 | 内容 |
|---|---|
| **2026 技术来源** | SkillOpt-Lite / HarnessOpt（arXiv:2607.03451）四步循环 + 三重护栏 + 统计死区 |
| **本项目的加强（关键）** | HarnessOpt 的验收是**任务指标 + 编译冒烟**；**本项目加一条"结构性验收"——修复后必须重测故障隔离与结构签名，退化即拒。** 这条对方完全没有 |
| **本项目资产** | 故障隔离 **92.6%（25/27，Δ28 pp）**、结构签名 sha256（可复算）、`StructureSignatureIndex`（diff）、24 门禁 |
| **验收** | 注入 N 类损伤 → 自愈成功率可测；**结构性退化补丁 100% 被拒** |

---

### D3 · 演化不用适应度函数（本方案最重要的一个决策）

**问题**：本项目 GA 实测 **8/8 seeds 输给随机搜索**（+29%）——显式 fitness 在此设计空间无增值。

**两条独立证据指向同一结论**：

| 证据 | 来源 | 结论 |
|---|---|---|
| GA 8/8 输随机搜索 | 本项目 Phase 3 实测 | **显式 fitness 在此空间无效** |
| 无显式适应度下仍有 ~40–50% 涌现 | 谷歌 arXiv:2406.19108 | **根本不需要 fitness** |

**设计**：

| 传统做法 | **本方案做法** |
|---|---|
| 用 fitness 打分排序 | 用**存活判据**二分：通过（24 门禁全绿 + 监护不退化）= 存活，否则淘汰 |
| 只保留精英 | 用 **DGM 式档案库**：**保留"有趣但非最优"的解作为垫脚石** |
| 单点最优 | 保留**结构多样性** |

| 项 | 内容 |
|---|---|
| **2026 技术来源** | 谷歌（无适应度）+ **Darwin Gödel Machine（ICLR 2026）** 的 archive 机制（保留非最优解作为垫脚石） |
| **本项目依据** | 本项目自己的 GA 负结果（8/8 输随机） |
| **验收** | N 代后种群**结构多样性可测**（用 `StructureSignatureIndex` 数独立结构数）；有门禁 |

> **这一条把本项目最痛的负结果变成了设计依据**——不是回避它，是用它做决策。

---

### D4 · 组合反应引擎（「结合出新东西」的核心）

**问题**：今天两个单元能"拼"（500 对可连接接口），但**拼出来是不是"新东西"没人判定**。

**设计**：把组合建模为**化学反应**——

| 化学概念 | 本项目对应（接口已核实） |
|---|---|
| **反应物** | 两个 organism / 功能单元 |
| **反应条件** | 端口类型兼容（`cortex.input` ↔ `cortex.output`）+ 连接类型的合法 `from_port → to_port` |
| **化学键** | **66 种连接类型**（带 `sign` / `fanout` / `span` / `delay_class` / `plastic`） |
| **反应规则** | **T3 规则引擎**：12 组合 + 7 嵌套 + 4 乘子（v2.52.0 已解锁） |
| **产物** | 一个新 organism |
| **产物判定** | ① 通过 24 门禁 ② **结构签名是新的**（不在 `StructureSignatureIndex` 中） |
| **"新能力"判定** | 新产物是否具备**任一亲代都不具备的可测能力** |

**"出新东西"的可测判据（不能是话术）**——三选一，必须能跑出来：

1. **结构判据**：新产物拥有亲代都不拥有的**模体/回路模式**（用拓扑层的有向 3 节点模体普查 + 结构签名判定）
2. **功能判据**：在给定任务上，新产物的表现**超出两个亲代的最优值**（需运行时 / LLM 访问）
3. **稳健判据**：新产物的故障隔离效应量**高于两个亲代**（用 92.6% 那套度量）

> **若三条都测不出"新"，就诚实记录"只产生了新组合，没产生新能力"。**
> **"结合出新东西"必须是可测结论，不能是宣传语。**

| 项 | 内容 |
|---|---|
| **2026 技术来源** | TMLR 2026 自进化综述的 **What**（演化什么）维度；DGM 档案库 |
| **本项目资产** | 116 单元 / 66 连接类型 / 83 端口 / 兼容矩阵（500 对）/ **T3 12+7+4 规则（已解锁）** / 结构签名 |
| **验收** | 产出 ≥1 个通过"新能力判据"的新物种；或**显式发布"仅新组合无新能力"的负结果** |

---

### D5 · 容纳层（Containment）：让演化不失控

**问题**：会自我修改 + 会繁殖的系统，第一风险是**失控**。

**设计**：安全保证**不放在模型里，放在容纳层**。

| 机制 | 内容 |
|---|---|
| **边界** | 端口是唯一通道；越界读写抛错并记录（D1 已含） |
| **配额** | 每个个体的步数 / 空间 / 能量配额；超额即终止 |
| **隔离** | 个体间不可直接访问彼此内部状态，只能经端口通信 |
| **死亡** | 终止判据：连续 N 代不达标 / 结构退化超阈值 → 终结 + **血统封存** + 资源回收 |
| **回滚** | 全部改动可 `git reset`；结构性变更包在特性开关里 |

| 项 | 内容 |
|---|---|
| **2026 技术来源** | **Containment Verification for AI Safety**（arXiv:2605.09045, 2026-05）——把安全保证 relocate 到容纳层；DeepMind **AI Control Roadmap**（2026-06） |
| **本项目资产** | 83 端口（天然边界）+ 24 fail-closed 门禁 + PROV（血统封存） |
| **验收** | 注入越界 / 超配额 / 失控繁殖 → 全部被容纳层拦下；有门禁 |

## 三、与北极星的关系（不再外围）

北极星 D1（**t≤k 步、不经全局读出、单模块直接决策**）在生命循环里是 **② 存活**阶段的核心能力——**应激**。

| 生命循环阶段 | 北极星的角色 |
|---|---|
| ② 存活 | **L4 应激**：局部回路快速响应 |
| ④ 自愈 | 局部回路先于全局检测到退化 → 触发修复 |
| ⑥ 选择 | 应激速度可作为存活判据之一 |

**这把北极星从"外围研究"纳入了主干**——它不再是单独的探索，而是生命的一个器官。

## 四、落地路线：Phase A–E

**原则**：每个 Phase 交付可跑的东西 + 一条"注入缺陷即报红"的门禁。**Phase A/B/C 零外部依赖。**

### Phase A · 让个体活起来（最小可活体）—— 零外部依赖，建议先做

| # | 交付 | 验收 | 状态 |
|---|---|---|---|
| A1 | **运行时**：输入 → 状态更新 → 输出 的代谢循环（自带，不依赖 SwarmLabs） | 给定输入序列可复现输出轨迹 | ✅ **v2.54.0**（`runtime.py`） |
| A2 | **边界强制**：端口唯一写入口，越界抛错并记录 | 注入越界 → 拒绝 + 报红 | ✅ **v2.54.0**（`PortViolationError` / `OutOfRangeError` / `UnknownPortError`） |
| A3 | **持续监护**：拓扑体检接入运行时（每 N 步测 ρ / 反馈边 / 模块度 / 结构签名） | 退化可报警；有门禁 | ✅ **v2.54.0**（`Monitor.check` 每 N 步，签名与 baseline 对比） |
| A4 | **代谢计量**：in/out 事件数、内部更新数、活跃节点比例 | 有数字；有门禁 | ✅ **v2.54.0**（`MetabolismCounter`） |

**产出**：第一个**活体**虚拟生物（此前全是标本）。

**门禁**：**Gate 25**（`scripts/check_runtime.py`，含 3 注入缺陷测试），20/20 selftest + 真实体双通道。`--quick` 21/21 PASS。

### Phase B · 让个体会自愈 —— 零外部依赖

| # | 交付 | 验收 | 状态 |
|---|---|---|---|
| B1 | **损伤注入器**：可复现的扰动（模块失效 / 接线断裂 / 端口污染） | N 类损伤可复现 | ✅ **v2.55.0**（`damage.py`：3 类损伤 + 确定性 + 失败即抛） |
| B2 | **修复算子**：`add_unit` / `rewire` / `drop_unit`（受端口兼容与连接类型约束） | 补丁可枚举、可回放、可反向 | ✅ **v2.55.0**（`repair.py`：4 种补丁 + apply/reverse 逆运算不变式 + 序列化往返等价） |

## 六、诚实边界

1. **今天这四条特征全部为 0**：无运行时、无自愈、无繁殖、无演化。本方案是**设计，不是现状**。
2. **不主张意识、感受或哲学意义上的"活着"。** 数字生命 = 一组可测的工程判据。
3. **不宣称计算力 / 能耗优势**（0/7、0/24 实测为负）。本方案**不重开**这两条；
   但 E2 可能解释 0/7 是基底问题而非结构无效——**待验，不是结论**。
4. **"出新东西"必须落到三条可测判据之一**，测不出就发负结果。**不接受"感觉上更强了"。**
5. **演化可能失败**。谷歌自己给出 SUBLEQ 反例（数十亿次执行不涌现）。C5 已预先声明关闭条件。
6. **D3（不用适应度）是有风险的决策**——它依据本项目一条负结果 + 谷歌一条外部结果。
   若 C 阶段长期无进展，**应回退检验这个决策本身**，而不是无限加代数。
7. **D/E 的功能判据需要 LLM 访问**，这是本项目当前不具备的新外部依赖，需确认可行性。
8. **外部数字来源强度**：AdaptOrch 是**单作者预印本**；谷歌 2024 论文自陈**非生物起源证据**。
   方向性可用，**具体数值对外引用前须核对原文**。

## 七、执行顺序（**已决策 2026-10-10**）

> **A → B → D（结构判据）→ C → E**
>
> - **A、B** 零外部依赖且是全部前提（没有心跳，后面都免谈）
> - **D-结构判据 提前到 C 之前**：因为"组合出新东西"是用户最关心的特征，且**结构判据零依赖**，
>   可以在没有 LLM 的情况下先做出结论
> - **C（种群演化）放 D 之后**：它依赖 A/B 稳定，且是四条特征里风险最高、最可能出负结果的一条
> - **E（P1 结案实验）作为收尾**：延后到 Phase A / B / D 完成之后，需 LLM 访问
>
> ### 对外节奏约束（**完全封闭期**）
>
> **Phase A / B / C / D 期间**：**不做对外沟通、不发论文、不发 preprint、不接触 VITAL / KAIST 等外部学术圈**。
> 全部封闭，直到 Phase A-D 全部有可复算的实测结果。
>
> **对外启动时机**：**Phase A-D 全部完成之后**（即四条数字生命特征至少各有一条实测非零结果）。
> 届时才启动对外动作：
> - 论文投稿：结构退化度量 / 跨物种 role 绑定 / 结构证据库方法论 / 262 雄性专有类型
> - 学术对接：KAIST Daeshik Kim（同 MaleCNS 基底）/ AdaptOrch 作者 / VITAL 国际联盟筹建期
> - 开源策略：Tier-2 IP 保持私有，L0 白皮书 + L1 半开放按用户后续决策执行
>
> **理由**：项目当前 4 条数字生命特征 = 0，"结构证据"只是评价框架不是终点。
> 若在 Phase A-D 完成前对外，学术圈会看到一个"只有证据库、没有活体"的项目，
> 声誉成本 > 收益。**把"证据 + 活体"一起交付**，声誉成本最小、技术壁垒最高。
