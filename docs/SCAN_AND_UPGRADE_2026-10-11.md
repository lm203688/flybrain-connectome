## 第二部分 · P1 结案实验的独立复核（本次扫描最重要的部分）

### 2.1 P1 报告声称的结果

`docs/p1_experiment_result.md` 的结论：

| 声称 | 数字 |
|---|---|
| 方向反转 | v2.36.0 GA **0/7 全输** → P1 warmup **4/4 全赢** |
| 整体提升 | warmup **+16.7pp**；full 跑出 **+33.4pp**（本次现测） |
| 4/4 拓扑一致 | fan_out +0.332 · hierarchical +0.361 · router +0.318 · sequential +0.327 |
| 判定 | "部分支持（partial positive）"；"**推翻了我们之前的 0/7 结案判断**" |

### 2.2 我的独立复核：按任务类型拆分

我对 `_p1_full/state.json`（1,284 cells）做独立分析，按 `task_type × condition` 拆分：

| task_type | evidence | random | **Δ** | n(ev) | n(rd) |
|---|---:|---:|---:|---:|---:|
| hub | 0.773 | 0.722 | **+0.051** | 300 | 126 |
| **motif_family** | **0.973** | **0.000** | **+0.973** | 300 | 132 |
| reachability | 0.763 | **0.833** | **−0.070** | 300 | 120 |
| **整体（含 motif）** | 0.837 | 0.503 | **+0.334** | 900 | 378 |

> **整个 +33.4pp 的效应，几乎全部来自 `motif_family` 这一个任务类。**

### 2.3 决定性发现：random 组的 `motif_family` 任务**在构造上不可能得分**

证据链（三层，全部来自代码与数据）：

**第一层 · 数据**：random 组所有 blueprints 的 motif 都是 `mixed`
```
evidence: recurrent_feedback 360 · reservoir_smallworld 288 · inhibitory_hub 252
random:   mixed 378   ← 全部
```

**第二层 · 代码注释（项目自己写明的）**：
```python
# llm_tasks.py:272
motif_family="mixed",  # label only; not among MOTIF_FAMILY_LABELS
```

**第三层 · 打分逻辑**：
```python
# llm_tasks.py:339
return a in MOTIF_FAMILY_LABELS and a == ground_truth
```
而标签菜单只有 3 个（`inhibitory_hub` / `recurrent_feedback` / `reservoir_smallworld`），
prompt 要求"Answer with EXACTLY ONE of these tokens"。

**→ 由于 `"mixed" ∉ MOTIF_FAMILY_LABELS`，random 组的 `motif_family` 得分恒为 0。**

**实测印证**：random 组 motif_family 的 `predicted` 分布是
`reservoir_smallworld 93 · recurrent_feedback 33 · No 3 · False 3` —— **模型在正常作答，但答案永远不可能被判对**。

### 2.4 修正后的结果

**剔除在对照组不可得分的 `motif_family` 后**：

| task_type | Δ | 方向 |
|---|---:|---|
| hub | **+0.051** | evidence 略优 |
| reachability | **−0.070** | **random 更优** |
| **净结果** | **≈ −0.01** | **无一致优势** |

> **结论：P1 没有推翻 0/7。**
> **在两组都可作答的任务类型上，证据锚定拓扑与随机同规模拓扑没有可靠差异**（一项微正、一项微负）。

### 2.5 为什么这个错误容易发生（机制分析）

| 环节 | 问题 |
|---|---|
| **任务设计** | 三个任务类型中，只有 `motif_family` 依赖 motif 标签；而 random 蓝图**没有真实 motif**，只能标 `mixed` |
| **聚合方式** | 报告用**总体均值**呈现结果，掩盖了任务类型间的结构性差异 |
| **验收缺失** | **没有"对照组可得分性"检查**——若有一条门禁断言"两组在每个任务类型上都存在可得分样本"，这个伪效应当场就会暴露 |
| **表述放大** | 报告用了"**方向反转**""**推翻 0/7 结案判断**"这类强表述，而证据只支持"partial" |

**这条经验对项目的科研纪律有直接价值**：
> **在对照实验里，"对照组能不能得分"必须先于"谁得分高"被验证。**
> 这是 §五 建议新增的**自验证纪律 S6**。

### 2.6 附带的审计缺陷：Gate 30 未注册且失败

| 项 | 状态 |
|---|---|
| 注册 | ❌ `check_llm_orchestrator.py` 自称 GATE 30，但**未进 `run_gates.py`** → 永不执行 |
| 断言 1 | ❌ `hierarchical: evidence block was never injected into any prompt` |
| 断言 2 | ❌ `defect 3. router ignores closed menu` 未触发 |

**断言 1 我已定位根因**：`hierarchical` **功能上确实注入了** evidence（经 `_wrap`），
但它的 **trace 记录的是未包装的原始 prompt**，所以审计链上看不到 evidence。
（对比 `sequential`：第 2 条 trace 记录 `wrapped_2`，含 evidence，故通过。）

**→ 这是审计缺陷，不是功能缺陷。但它的后果严重**：
**P1 的 hierarchical 臂无法从 trace 证明 evidence 真的进了 prompt**，
在"可复算"标准下该臂的结论不可验证。
