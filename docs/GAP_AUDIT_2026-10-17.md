### G1 ★★★ 收据系统 5/9 实测失守，且无任何门禁守护

**证据**（`python scripts/verify_receipt.py --receipt receipts/<id>.json` 逐份实测）：

| 收据 | 状态 | 失效原因 |
|---|---|---|

**根因（两条，都已实测确认）**：
1. **v2.95 的 K5 重构改了所有被收据哈希的脚本**——`c1/c3/f1/f3/f4b/f6/mechanism_binary/check_metric_substitution` 八个文件全部改成导入 `_metrics_compat`，而 R1/R2/R3/PR2b/PR4 恰好覆盖其中六个。**改脚本不重签收据**。
2. **R2 还叠加数据文件问题**：`run_gates.py:219` 的 Gate 31 每次跑批用 `--output-dir _gate31_r2` **重写数据文件**。实测重跑是确定性的（两次重跑 SHA256 一致：`0f175958088e5c2d…`），但**已提交版本是旧代码生成的**（git diff 显示键序漂移）——跑一次门禁就改写活文件，R2 收据哈希的是旧版本，于是"跑门禁→破收据、提交新数据→收据哈希又变"的死循环。

**更严重的是守护层缺失**：`grep -rn "verify_receipt" scripts/run_gates.py .github/workflows/ci.yml` → **零命中**。badge 门禁（Gate 50/56）只检查"V5 主张有收据文件在盘上"（存在性），从不验证内容。所以 53/53 全绿与 5 份收据失效可以同时成立——**这正是"门禁绿但地基裂"的教科书案例**。

**为什么是 P0**：收据是 VRO/EPE 叙事的核心承诺——"不信任作者的第三方也能验证"。P-4/P-5 论文如果引用收据体系，审稿人跑一次 `verify_receipt.py` 就会看到 5/9 MISMATCH。

**修复**（约 2 小时）：
1. 按当前脚本重新签发 R1/R2/R3/PR2b/PR4（`issue_receipt.py`）；
2. 提交 Gate 31 重生成的数据文件（已实测确定性，重生成后提交一次即稳定）；

## 3. P1 级缺口（声明与实现的偏差，合计约 4 小时）

### G4 ★★☆ K5 fallback 正确性无人背书

`scripts/_metrics_compat.py` docstring 声称纯 Python 回退实现"与 metrics_kernel 数值一致"，但：
- **没有任何测试验证 fallback == kernel**（grep tests/ 无 fallback 测试）；
- `_kernel_bridge.py`（K5 的核心桥，连接 compat 层与 kernel）**无单测**（11 个模块中 5 个无测试：protocol/cli/redteam/__main__/_kernel_bridge）；
- fallback 路径只在"flybrain-core 未安装"时触发——CI 恰好不装它（`pip install numpy dataprov`），但 CI 又不跑相关门禁（G2），**两条盲区叠加**。

**修复**（约 1.5 小时）：写一个属性测试——随机 200 组 (scores, labels)，断言 `_fallback_auc == kernel.auc`（容差 1e-12），纳入 K9 测试套件。这是"声称等价"变成"机器验证等价"的关键一步。

### G5 ★★☆ K8 阈值脱钩是 warn-only 设计

- `_warn_threshold_drift()` docstring 明写 *"打印阈值漂移警告（**不失败**）"*——漂移 >2x 只打印 `[WARN]`，门禁照常 PASS。
- METRICS 里的 `min_variance` 仍是手写字面量（0.35/0.035/0.002…），校准代码只是"复算 + 比对 + 落盘报告"。
- 校准集是 36 个**随机图**（`_random_calibration(seed, n=10, density=0.12/0.55)`），"独立性"靠名称集合零重叠检查——统计上独立，但随机图与真实 MaleCNS 拓扑的方差结构差异大，用随机图校准真实拓扑阈值，校准本身的有效性没有论证。

**定性**：比上轮（纯注释）进步巨大——已机器可复算、有报告落盘、有独立性检查。但"K8 阈值脱钩"的完整含义应是**漂移即 FAIL**。当前实现是"可复算 + 可警告"，属 70% 完成态。

**修复**（约 1 小时）：把 `_warn_threshold_drift` 的 >2x 分支改为 `sys.exit(1)`（或返回失败标志），并给出阈值更新流程说明。
